# Arjun locomotion AnimationTree — 2026-09-25

`player/arjun_motion_tree.gd` builds a Godot AnimationTree from the gameplay GLB's idle, swim idle, and swim forward clips, plus a runtime walk gait for the same rig. The imported walk held the hands near the hips with little visible stride, so the runtime gait adds alternating legs and opposite arm swing without changing the source GLB. The gait is based on the imported idle pose rather than the rig bind pose. Ground and water each use a one-dimensional blend; a final blend moves between them. The clips loop in memory, and the baked Root position track is removed so the CharacterBody3D controls travel and collision.

`player/arjun_visual.gd` advances the tree manually from actual horizontal speed and swimming state. Ground playback cadence increases with travel speed to reduce sliding. The visual rig lowers toward the lowest foot during walk phases; it does not move the collision body. The old forward model tilt is removed while the imported swim clip is active because that clip already pitches the body forward. Existing procedural poses still handle prone, cover, river actions, climbing, riding, weapon grip, and attacks. Those systems still need visual tuning and transition review. The tree is a locomotion foundation, not a completed animation set or an approval of Arjun's rejected temporary appearance.

Focused checks: `tools/characters/validate_arjun_motion_tree.gd` prints `ARJUN MOTION TREE: PASS` for idle/walk pose difference, speed cadence, bounded foot correction, water blending, and root track setup. `tools/characters/validate_arjun_visual_tree.gd` prints `ARJUN VISUAL TREE: PASS` for player speed feed and no second swim pitch. `tools/characters/capture_arjun_motion_tree.gd` produced fresh Forward+/Metal [idle](animation_tree_idle.png), [walk A](animation_tree_walk_a.png), [walk B](animation_tree_walk_b.png), [walk side](animation_tree_walk_side.png), and [swim](animation_tree_swim.png) captures on Apple M4. The side frame shows one boot near the floor and one in swing, but planted contact through the full cycle, travel speed, and normal-speed transitions remain unapproved. These captures use the temporary appearance that the owner rejected and must not be used for appearance approval. Full-world validation also remains open while concurrent terrain changes are in progress.
